# Priority fixes: grounding, measurement and stack consolidation

Approved by the user on 2026-09-16 ("make these priority updates, overall make project solid so that production grade AI agent workflows can be accommodated"). Scope is the six priorities from the 2026-09-16 review, not the longer roadmap the user also shared; that roadmap's phases 3–4 (approvals, action ledger, parallelism, published versions) are deferred until the knowledge assistant is measured and dependable.

## Decisions
- Put the project under Git before any change (baseline commit of the 2026-09-15 state) and back up the user database to `.data/backups`. Relocating the checkout out of iCloud is the user's call and was not done.
- The Retrieve → Agent path carries the Query node's grounding contract: rendered numbered passages instead of the raw JSON envelope in the prompt, `[S#]` citations validated against the evidence, invented labels rewritten to `[unsupported reference]`, post-generation source re-verification, insufficient-evidence reply without a model call when the evidence set is empty, and a new `sources` output on the Agent node so the run panel can mark cited passages.
- Ollama discovery carries per-model capabilities from `/api/show`. Knowledge-base configuration and indexing require an embedding-capable model; the chat picker hides embedding-only models; an existing index keeps answering with the model it was built with.
- Evaluation is a checked-in synthetic corpus (20 handbook documents, 45 labelled questions including paraphrases and unanswerables) plus `scripts/eval_retrieval.py`, which runs the real services in-process with real Ollama embeddings in temporary storage and optionally grounded generation through the workflow runtime. Metrics: document recall@1/@k, MRR, passage-level answer@k, answer accuracy, false abstention, abstention on unanswerables, citation rate, citation faithfulness, unsupported references, latency. No cloud calls.
- Hybrid fusion min–max normalises each candidate list before the weighted combination; ties resolve by semantic rank for repeatability. RRF is unchanged.
- The legacy PDF knowledge stack (`knowledge.py`, `knowledge_api.py`, `knowledge_nodes.py`, PDF retrieval and Grounded answer nodes) and the canvas vector-resource stack (`vector_service.py`, `vector_api.py`, VectorDB nodes, store edges, `kb_migration.py`, `check_platform.py`) are removed. Shared option models moved to `backend/app/kb/options.py`; chunking moved into `kb/ingestion.py`. `storage_path` stays on Retrieve/Query as an ignored field so saved JSON keeps loading. Prompt template and Language model remain hidden but loadable. Old `knowledge_*`/`vector_*` tables in existing databases are ignored. The provenance guarantees (evidence checked on API resume, lease recovery and cached replay) were rewritten against the knowledge services rather than dropped.
- The user's real workspace: `llama3.1:latest` enabled in the model catalog; the saved workflow and knowledge base untouched. The existing knowledge base uses `qwen2.5:0.5b` as its embedder and should be rebuilt with `embeddinggemma:latest`.

## Verification
Backend and frontend suites, typecheck, lint and production build must pass. Retrieval and generation measured before and after each change with fresh outputs. The six saved questions re-run through the real worker against the live knowledge services on a copy of the user database. No paid model calls, no external writes, no browser QA.
