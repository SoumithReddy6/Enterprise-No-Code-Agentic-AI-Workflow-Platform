# Unified Knowledge Base services

Approved implementation scope: named KB management outside the canvas; independent management, ingestion and retrieval/index service processes; original general workflow flexibility retained. User approval: proceed with code implementation after architecture and cross-service consistency discussion.

Management owns KB configuration versions, document metadata/original blobs, durable job leases and activation. Search owns immutable attempt segments, chunks, keyword postings and vector artifacts. Ingestion owns temporary processing only and calls both service APIs. Separate DB URLs and authenticated internal RPC; no cross-service table writes. Local SQLite defaults and PostgreSQL supported. Public API under /api/knowledge-bases; gateway resolves user identity and encrypted shared connection. Search and ingest use matching pinned Ollama model digest and dimensions. No automatic model downloads/paid calls.

Each upload registers metadata + durable job atomically; content hash/idempotency key detects replays. Each build uses a unique attempt ID, durable lease, visibility gated by active published manifest. Rebuild creates pending configuration and indexes all live documents, then atomically activates after all succeed; old active remains if failure. Uploaded files stay tracked after indexing failure. Cancel/delete invalidates publication immediately. Failed attempts and retired segments use durable retryable cleanup inventory; late writers cannot publish or escape eventual repeated cleanup. Source download/search/resume check ownership and active deletion state. Old successful version stays searchable during replacement/rebuild; no foreign-workspace results.

UI: unified KB list/detail, name/description, storage backend/path/index, installed embedding model, fixed/paragraph chunk strategy+size+overlap, documents/status/retry/remove/replace, rebuild/cancel, search playground with retrieval modes/defaults/filters/sources, activity and cleanup state. No vector nodes in new palette; preserve hidden old nodes, legacy knowledge workflow routes and histories. Retrieve/Query select KB by ID with name display; supports standalone flow or callable attachment. Structured evidence travels via JSON string envelope with original question, passages and sources, preserving Workflow v1 string ports. Preserve current working user account and data; backup before migration/restart.

Limits:25MB/file,200pages,20 active documents/KB,50k chunks/workspace,20 results, bounded batch embedding & attempt retries, timeouts. Supportedfiles PDF/TXT/MD/CSV/JSON/HTML/DOCX, clear unsupported errors. Preserve old stores read-only during migration and preserve source endpoints. Test actual failure/retry/cleanup/tenant isolation/rebuild/version/cachedsource paths. Live testing temporary data only. No remote writes beyond local test Docker/Ollama. No Git repository; no Git initialization.
