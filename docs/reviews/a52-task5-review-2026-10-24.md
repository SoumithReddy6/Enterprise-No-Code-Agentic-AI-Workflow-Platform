### T5-01 — S21b omits contract-1 run submission

Location: `scripts/scenarios/switch_routing.py:106–115`.

The HTTP-input workflow is tested through both `/api/validate` and `/api/runs`.
The contract-1 workflow is tested only through `/api/validate`. Therefore the
published scenario does not yet permanently cover the claimed submission boundary
for both refused workflow forms.

The independent review submitted the same structurally valid contract-1 Switch
workflow through `/api/runs`. It returned 422 with the specific contract-2 error,
created no run row, and caused no model or receiver calls. Product behavior is
correct; the missing assertion belongs in the retained scenario.

Suggested change: submit `old` to `/api/runs`, assert 422 and the specific error,
and compare run IDs and external-call counts before and after submission.

### T5-02 — Reference implies every write requires an approval pause

Location: `docs/multi-way-routing.md:44–45`.

The statement that a write after a case named `approved` "still waits for its own
write approval" is unconditional. Normal node/run approval settings still apply:
S20 explicitly sets `approval: false`, while S21c enables it and proves the pause
and rejection behavior. This distinction matters to workflow authors deciding
whether a send requires a person.

Suggested wording: "A case id or label grants no permission. A case named
`approved` cannot bypass checked-value eligibility or any approval required by
the write's configured policy."
