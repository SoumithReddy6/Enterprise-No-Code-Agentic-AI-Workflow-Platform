## R01-I01 — P1: a Response saved after loop resume bypasses the hidden-source check

Location: `backend/app/worker.py:200` (`validate_cached`); related
`platform_validation.py` dependency-owner selection and compiler's restored-output path.

`validate_cached` passes only `{node.id: outputs}` as the checkpoint map. At a cached
Response, a saved owner such as `each:0` is therefore neither a checkpoint key nor covered
by a loop checkpoint in that map. Because `loop_progress` was deliberately omitted, the
owner is skipped. The new `reused_dependencies` union lives in `response_node`, which does
not run when the compiler restores a Response checkpoint.

The fresh Response path is protected. A cached Response originally saved after a loop
resume can have `sources: []`, however, so checking only its displayed source list is
insufficient. Preflight and earlier loop validation cannot cover removal before this later
Response reuse.

### Reproduction on the actual implementation

Real temporary KB management/search/indexes, ingestion/removal, SQLite and Worker; fake
provider and Jira transport. The source is a document containing the Bluebird codename.
An unrelated document keeps the KB available after removal. No database tampering or
malformed record is used.

```text
Input → Jira list → For each (Query body) → Prompt formats each.results → Response
```

1. Attempt 1: Query finishes; stop immediately after the loop checkpoint commits.
2. Attempt 2: resume with the document present. The loop restores its text without putting
   the passage back into the evidence registry. The fresh Response correctly verifies the
   hidden dependency and saves an answer with `sources: []`. Stop immediately after that
   Response checkpoint commits.
3. Attempt 3: resume with the document still present. Preflight and cached-loop checks
   succeed. Let the cached Prompt commit, then remove the document before Response reuse.
4. The cached Response passes validation without checking `each:0`, emits cached success
   and the run publishes the removed document's answer text.

Observed:

```text

output contains: Bluebird is the project codename.
cached Response sources: []
checks after removal: 0
cached Response republished: true
provider calls across all three attempts: 1
```

The output marks the old citation unsupported but retains the source-derived fact. This
is a new publication/reuse, not merely reading retained run history. It is also not the
accepted interval after a final Response authority check: no check of that dependency is
made at this reuse boundary.

U7 starts with a Response whose displayed sources are nonempty. U22/U23 exercise a fresh
Response after loop reuse. All can pass while this composition of the two paths fails.

## Published basis

[Saltzer and Schroeder](https://web.mit.edu/Saltzer/www/publications/protection/Basic.html)
include recovery in complete mediation and warn that a remembered authority check becomes
stale when authority changes. Applied here, passing preflight cannot replace checking the
dependencies behind the later cached Response. The specific omission and correction are
established by the code and reproduction, not prescribed by the paper.

[CWE-367](https://cwe.mitre.org/data/definitions/367.html) supports retaining the documented
check/commit limitation. That limitation does not cover skipping the dependency entirely
at this final reuse boundary.
