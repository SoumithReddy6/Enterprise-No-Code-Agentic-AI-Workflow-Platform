# S07 execution-policy audit — 2026-09-27

Audited working tree based on commit `4403109`, including existing uncommitted changes. No production code was changed for this audit. Deterministic probes use real compiler/policy execution with scripted model responses and stubbed external services; these are not fresh live-model or network penetration tests.

## Findings

### S07-01 — P1: action budget resets across resume

`backend/app/compiler.py:179-181` creates a new action budget on every compilation. `backend/app/worker.py:119` restores checkpoints, loop progress and approval frames, but not a general run budget or spent tokens. Approval frames cover only some pause paths.

Reproduction: two sequential agents share one attached tool and a budget of one. Interrupt after the first agent's success checkpoint and resume the identical workflow with those checkpoints. The second agent executes another tool action: two actions under a limit of one. This defeats the run-wide resource bound. Token totals also are not restored by this initialization path (confirmed by code inspection, not a separate token-resume probe).

Fix direction: persist authoritative counters under the worker lease and restore them before any pending node runs. Include retries and pause/restart paths; a checkpoint cache hit must not replenish budgets. The general resume-accounting gap predates parts of S07, but remains open under its shared-budget guarantee.

### S07-02 — P1: loop first attempts bypass the action ceiling

`backend/app/iteration.py:76-79` passes `charge_first_attempt=False`. The policy debits only retries in this mode. Direct graph tools use the same setting. The runtime therefore counts an agent-selected tool invocation but not the same tool invoked directly by a loop.

Reproduction: `AGENT_RUN_BUDGET=1`, three Jira items, a Python body: all three body calls execute. This is a mismatch with the approved per-attempt shared action budget. There are still separate loop-size and run-time limits; this is not unlimited execution.

Fix direction: define billable/action-bearing attempts explicitly and charge their initial attempts as well as retries. Triggers and response rendering can remain free. Ensure approval replay and durable-result replay are not charged as new external attempts.

### S07-03 — P2: non-model tool events inherit parent usage

`backend/app/execution_policy.py:51-55` falls back from absent invocation usage to the checkpoint owner's total. Absence is normal for a tool that calls no model. `agent_runtime.py` now publishes this result on target outcome events, and the parent also publishes its own usage. `operator_metrics.usage_rows` consumes all non-cached usage events without deduplication.

Reproduction: an agent makes two model calls at ten tokens each and one Python call. Events report `calc success: 10`, `agent success: 20`: 30 reported tokens for 20 actual tokens. This contradicts the preceding implementation's claim that nested accounting was fixed. Run token enforcement reads the original aggregate and is not itself inflated by these duplicate events.

Fix direction: an invocation with no model usage must return no usage. Do not fall back to its owner's cumulative usage. Keep one authoritative accounting source rather than two independent accumulators.

### S07-04 — P2: retry events duplicate cumulative usage

`backend/app/execution_policy.py:97-98` publishes cumulative usage on each retry; the final outcome includes those same tokens again. This is independent of the parent-fallback defect.

Reproduction at the policy boundary: a callable records ten tokens and raises `TransientToolError`; its second attempt records ten and succeeds. Retry plus terminal usage sums to 30 rather than 20. The probe injects the post-spend transient failure; it does not claim a particular real provider currently emits that exception after billing.

Fix direction: either publish usage only on the accounting outcome or emit deltas with durable deduplication. Retry events can retain attempt and delay metadata without adding spend a second time. Include failed/cancelled/paused outcomes in accounting tests.

### S07-05 — P2: token precheck prevents free abstention

`backend/app/execution_policy.py:83` checks the token limit before invoking the caller closure. The compiler's answerability short-circuit lives inside that closure, and the agent's empty-evidence abstention is even deeper. Both can be blocked before they return a response requiring no model call.

Reproduction: first agent consumes a ten-token ceiling; retrieval then returns zero passages; the next grounded agent should immediately abstain. Instead the graph raises `Run token budget exhausted` and fails. This is a policy-ordering regression in the new seam.

Fix direction: resolve free guard/abstention outcomes before the paid-attempt token check, keeping upstream inspection in the caller as the design requires. Test both an explicit answerability denial and an empty evidence envelope.

## Evidence and limits

Probes are in `evals/results/s07-audit-2026-09-27/test_probes.py`; assertions express the intended behavior and intentionally fail on the audited implementation. They are outside `backend/tests` so ordinary test discovery of that suite stays unchanged. JUnit output is retained beside them.


All five probes reach their intended failure. In particular, the resume probe catches LangGraph's `NodeCancelledError` wrapper and proceeds to the resumed action-count assertion; it does not mistake a fixture exception for the finding.

Existing approval, uncertain-write and execution-safety tests were rerun separately: **101 passed** (JUnit: `evals/results/s07-audit-2026-09-27/existing-tests.xml`). No new approval bypass, duplicate delivery, cross-tenant access or credential disclosure was demonstrated in this audit. The budget findings concern resource containment; the usage findings concern accounting integrity. S08 and S09 are separate pre-existing campaign findings and are not counted here.

Recommended order: restore durable budgets and consistent attempt charging; correct usage attribution/deltas; move free abstention before the token check. Re-run production scenarios after fixes.
